# ⚙️ Фоновые задачи

Тяжёлый запрос не держит пользователя на странице. Сервер сразу отвечает `202` и выдаёт **тикет**,
а работу выполняет отдельный воркер. О том, как это устроено внутри Kafka, — в [Kafka](../engineering/kafka.md).

## Типы задач

| Тип | Что делает | Кому доступна |
|---|---|---|
| `demo_report` | демо-отчёт: журнал выполнения по шагам, длительность задаётся | всем вошедшим |
| `stock_report` | CSV со складом: артикул, товар, раздел, категория, цена, остаток, стоимость остатка, состояние, продано и возвращено за 30 дней | праву «Создание отчёта остатков» |

Для отчёта об остатках можно выбрать фильтр «мало» или «нет в наличии». Право проверяется дважды:
при создании и в воркере, потому что задача могла ждать в очереди, а право за это время отозвали.

CSV пишется с разделителем `;` и BOM: русский Excel открывает его без настройки.

## Что видит пользователь

1. Нажимает «Создать» — сервер отвечает тикетом (`POST /tasks`, не чаще 5 в минуту).
2. Страница задачи обновляется сама: **В очереди → Обрабатывается → Готово** (или **Ошибка**).
3. На любой странице сайта загорается «колокольчик» с уведомлением о завершении.
4. Результат можно скачать в течение 5 минут; на странице идёт обратный отсчёт. Потом файл удаляется,
   и скачивание отвечает 410.

Уведомления удаляются автоматически через 7 дней, прочитанные можно очистить вручную.
Опрос статуса ограничен 120 запросами в минуту, скачивание — 30.

## Сторож

`tasks:reconcile` запускается планировщиком каждую минуту и страхует конвейер:

- публикует задачи, которые не дошли до Kafka;
- возвращает в очередь зависшие в обработке (пока не исчерпаны попытки), иначе переводит в «Ошибка»;
- переводит в «Ошибка» задачи, которые никто не взял в течение часа;
- досылает потерянные события о завершении.

Если Kafka недоступна или нет топиков, команда завершается с ошибкой; это видно в `docker compose logs scheduler`.

## Команды

| Команда | Что делает | Когда |
|---|---|---|
| `tasks:consume` | воркер задач | постоянно, сервис `task-worker` |
| `tasks:notify` | нотификатор | постоянно, сервис `task-notifier` |
| `tasks:reconcile` | сторож | каждую минуту |
| `tasks:prune-results` | удаляет просроченные файлы результатов | каждую минуту |
| `notifications:prune` | удаляет старые уведомления | каждый час |
| `tasks:demo --seconds=5 --count=1 --user=` | создаёт демо-задачи для отладки | вручную |

## Настройки

Лежат в `config/tasks.php`; часть задаётся переменными окружения.

| Параметр | Переменная | По умолчанию | Смысл |
|---|---|---|---|
| попытки | — | 3 | сколько раз задачу можно взять в работу |
| зависание | `TASKS_STALE_AFTER_MINUTES` | 10 | через сколько обработка считается зависшей |
| ожидание в очереди | `TASKS_PENDING_TIMEOUT_MINUTES` | 60 | через сколько невзятая задача падает |
| хранение результата | `TASKS_RESULT_TTL_MINUTES` | 5 | как долго доступен файл |
| хранение уведомлений | `TASKS_NOTIFICATIONS_TTL_DAYS` | 7 | через сколько дней уведомления удаляются |
| пауза до сторожа | — | 60 с | сколько веб-запрос может публиковать задачу сам |
