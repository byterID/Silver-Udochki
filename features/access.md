# 🔐 Роли и права

Основа — `spatie/laravel-permission`. Поверх неё работает собственный слой: жёсткая иерархия ролей
и защита критичных прав. Настройки лежат в `config/access.php`.

## Роли

Уровень роли (`Enums/RoleName::level()`) определяет иерархию: действовать на пользователя можно только с уровнем ниже своего.

| Роль | Уровень | Права по умолчанию |
|---|---|---|
| Администратор | 100 | все |
| Менеджер | 50 | вход в панель, управление пользователями, акции (все четыре), склад (просмотр, изменение), отчёт об остатках |
| Покупатель | 10 | нет |
| Гость | 0 | нет |

Права выдаёт `RolesAndPermissionsSeeder`. Для сотрудников (уровень от 50) в панели есть список сотрудников, для покупателей — отдельный.

## Права

Каждое право имеет код (`Enums/PermissionCode`), название и группу действий.

| Группа | Права |
|---|---|
| Администрирование | вход в панель управления, настройка прав и ролей |
| Пользователи | управление пользователями, выгрузка пользователей |
| Акции | просмотр, создание, изменение, удаление |
| Склад | просмотр склада, изменение остатков |
| Создание отчёта остатков | выгрузка отчёта об остатках |

Отчёт вынесен в отдельную группу, чтобы выдать его роли, не открывая ей склад.
Доступ к разделам панели определяется только правами. Право на вход в панель не открывает разделы:
у каждого раздела своё право.

## Правила

Политика `UserPolicy` запрещает менять и удалять пользователя:

- с равным или более высоким уровнем;
- самого себя (собственные данные меняются через профиль).

При включённом `strict_hierarchy` роль можно назначить только ниже своей.

Страница «Управление доступом» дополнительно защищает права от ошибок:

| Защита | Что делает |
|---|---|
| Закрепление | критичные права (`access_control_panel`, `manage_access`) нельзя снять с роли администратора |
| Эксклюзивность | право `manage_access` нельзя выдать никому, кроме администратора |
| Без повышения | нельзя выдать право, которого нет у самого выдающего |
| Своя и высшая роль | менять права роли с уровнем не ниже своего может только суперадминистратор |

## Администратор и новые права

- Первый администратор создаётся сидером из `ADMIN_EMAIL` и `ADMIN_PASSWORD`; существующему пользователю роль выдаёт
  `php artisan app:make-admin <email>`.
- Новые права добавляются **data-миграцией**, а не только в сидере: деплой запускает только `migrate`, сидеры на сервере не выполняются.
  Пример — `add_promotion_permissions`.
